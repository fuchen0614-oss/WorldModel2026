| | 期刊线（TGRS/TIP） | ICLR |
|---|---|---|

## 1. 前情提要：三条负结果如何约束后续设计

在讨论"补什么实验"之前，必须先正视**三条负结果**——它们不是失败，而是精确定位了方法边界。

### 1.1 三条负结果的准确表述

| # | 结果 | 准确含义 | 后续约束 |
|---|---|---|---|
| **一** | **Q4（组合律）未成立** | real/shuffled composition ratio ≈ 1 只说明状态没坍缩，不支持任何组合主张 | **不得用 Q4 充数**；要做就先改模型成递归转移（属新方法，不属补实验） |
| **二** | **future-state anchor 消融反向** | 去掉它，OOD-t 上 R²/RMSE/official ΔR²/paired ΔR² 四项全部略好 | **不得写进 method 必要组件**；不为它补跑 Q3；只留内部记录 |
| **三** | **exclusive 路线精度不足** | R²=0.49027 低于 0.502 门槛；closure paired CI [-0.00226,+0.01768] 跨 0 | **不得跨 checkpoint 拼接**（Phase-I 精度 + exclusive 机制） |

### 1.2 负结果的正面含义

**Q4 不成立的根因**是"没有递归状态转移"（direct-horizon 接口，每个 h 从同一 z_t 直接查询）。**这恰好就是 ICLR 线需要补的东西**——可组合转移。

> 负结果不是坏消息，它精确定位了方法缺口。但必须诚实：那是**改模型**，不是补实验。

**由此推出的设计纪律**：
1. 任何"补实验"方案里不得出现 Q4 充数
2. future-state anchor 不写进必要组件
3. 不得跨 checkpoint 拼接
4. **跑任何新消融前必须预注册"某臂反而更好怎么写"**（这是 anchor 消融留下的教训）
5. ICLR 线的改模型方向已被负结果指明（补可组合转移）
6. 期刊线不能靠机制证据撑场（Q4 没有、anchor 反向，只剩 Q2/Q3）

## 2. Q1–Q3 现状速览

### 2.1 已经成立的证据链

| 问题 | 证明了什么 | 证据强度 |
|---|---|---|
| **Q1** | 在 GreenEarthNet OOD-t 上保持有用预测能力（R²=0.56935 / RMSE=0.15059） | ✅ 成立，但主表第六 |
| **Q2** | 状态路径对预测是 load-bearing（OOD-t: official ΔR²=0.01997，paired ΔR² CI [0.01422, 0.03018]） | ✅ 成立，比"网络有个叫 state 的张量"强得多 |
| **Q3** | 真实未来天气比 donor/mean 产生更忠实的完整窗口预测（84 对极端子集：actual 0.625 > donor 0.589 > mean 0.543） | ✅ 成立，但不等于因果反事实 |

### 2.2 当前明确不成立或未证明的内容

1. Q3 不证明严格因果反事实
2. hot-dry enhancement guard 未通过
3. Q4 composition 不成立（见 §1.1）
4. 不是递归 rollout 世界模型
5. 主要输出 NDVI，不是完整多光谱影像
6. 没有独立分类/分割/检测下游
7. 未在多个独立数据源证明广泛泛化
8. Q1 核心价值是"预测前提成立"，不是榜首精度

### 2.3 当前"世界模型"成分的准确边界

> **被严格证实的只有两条**：状态承载预测（Q2）、天气响应保真（Q3）。  
> 组合性没有、递归动力学没有、future-state anchoring 的必要性没有。

这不是失败——Q2+Q3 已经比 EO-WM/VegSim 的输出层诊断更硬。但它决定了**扩展方向必须是"补上缺的那一层"，而不是"把已有的再横向铺开"**。

## 3. 为什么两个 venue 要分开设计

| 维度 | 期刊线（TGRS/TIP） | ICLR |
|---|---|---|
| 要的新意 | 方法/算子的技术贡献 | **概念或机制的洞察** |
| 实验广度 | 分层、鲁棒、效率、多数据集 | 假设-验证闭环，可窄但必须锐利 |
| 对精度 | 较高（读者要可用性） | 较低（若洞察够强） |
| 协议创新 | 次要 | **可以是主贡献** |
| 输出形态 | 偏好图像/多通道（TIP 尤甚） | 不关心是 NDVI |
| 负结果 | 不受欢迎 | **可以是贡献**（若能解释清楚） |
| 数据集数量 | 实践上 2–3 个 | 1 个真实 + 1 个受控即可 |
| 改模型 | 可不改（TIP 除外多光谱） | **必须改** |

**关键判断**：

> 「增加两个遥感数据集和三个下游任务」是期刊式扩展；  
> 「提出一种在部分观测下学习外生驱动可干预状态、并能向未见驱动外推的方法」才是 ICLR 贡献。

**两条路的冲突点**：
- TIP 需要的多光谱输出改造，对 ICLR **零收益**
- ICLR 需要的可组合转移+模拟器对齐，对期刊边际收益低
- TIP 追精度，ICLR 要证明精度≠机制（方向相反）

**共用的部分**：完整 OOD 矩阵、四维分层、训练级消融、跨模型机制测量——**这些做完前不必选边**。

## 4. 期刊线实验扩展（按重要性/优先级排序）

> **前提假设**：若 AAAI 未中，转投遥感期刊；你接受加新数据集。  
> **venue 选择张力**：你倾向 TIP；Codex 调研结论是 TGRS 更合适（见 §4.1）。  
> **对标案例**：VegeDiff（TGRS 已发表）——唯一数据族 + 深度实验能过关。

### 4.1 ⚠️ 未解决的 venue 张力（必须先裁定）

| | TGRS | TIP |
|---|---|---|
| **全称** | Transactions on Geoscience and Remote Sensing | Transactions on **Image Processing** |
| **Scope** | 遥感数据处理与解释中的新方法 | 图像/视频/多维信号处理，遥感是应用之一 |
| **对 NDVI 单通道的态度** | ✅ 接受 | ⚠️ 需补多光谱+图像质量指标 |
| **近邻先例** | **VegeDiff（唯一数据族+深度实验）** | 无明显世界模型范式 |
| **Codex 建议顺序** | TGRS → JSTARS → ISPRS | 需重构为"外生条件时空影像预测" |
| **多光谱改造** | **不需要** | **几乎必需**（分水岭） |

**我的建议（但这是你的决定）**：先按 TGRS 路线设计实验，因为：①VegeDiff 已证可行；②省多光谱改造；③遥感专业审稿人更懂这个任务。若后续确定要投 TIP，再启动多光谱改造（见 P2）。

### 4.2 P0：完整 OOD 矩阵（消除"仅时间偏移"的 Limitation）

**内容**：Q1+Q2 扩到 `iid` / `ood-s` / `ood-st`。

**数据**：本机全有（iid 2,856 / ood-s **10,536** / ood-st 7,024 cube），结构与 ood-t 完全一致。



**为什么 P0**：
- 直接消除正文 Limitation 里"仅时间偏移"那句
- GreenEarthNet 的核心贡献就是 ood-t/s/st 完整矩阵，我们用了数据却只报了 1/4
- `ood-s` 有 10,536 cube（ood-t 的 5.5 倍），这是**最便宜的实质性增量**
- 两个 venue 都要（期刊要广度，ICLR 要鲁棒性）

**预期风险**：Q2 可能在某个 split 上不显著 → 但这本身是有价值的负结果（"状态承载性在空间偏移下退化"也是发现）。

### 4.3 P1：四维分层分析（从"数据描述"到"实验证据"）

**内容**：按云覆盖比例 / 有效帧数 / 最长连续缺测 / lead-time / 土地覆盖 四个维度分层报告 Q1+Q2。

**数据**：`s2_avail`、`s2_dlmask`、`s2_SCL`、`esawc_lc`、`geom_cls` 全在 cube 内，**零下载成本**。

**为什么 P1**：
- 摘要写 "infers a spatial predictive state from cloud-masked histories"，但**没有任何实验以云遮挡为自变量** → 这是数据描述与实验证据之间的空洞
- 期刊审稿人会细读 Limitation，这一条能填补"为什么不分析云影响"
- VegeDiff 做了逐时域、多指数、降水扰动分层 → 我们做云/LC/lead-time 是同一逻辑
- Lead-time 曲线（状态贡献随 horizon 分布）是**几乎零成本但很有说服力**的一张图

**预期产物**：
- 云遮挡曲线：x 轴云覆盖% → y 轴 Q1 精度 + Q2 状态贡献
- 有效帧数曲线：x 轴有效帧数 → y 轴同上
- Lead-time 分解：horizon 1–20 的误差 + 状态 residual 幅度
- 按 LC 分层表（forest / grassland / cropland / urban 等）

### 4.4 P2：训练级 4-arm 消融（升级"测试时切路"为"训练级必要性"）

**内容**：四臂矩阵——context-only / +state(无 L_fs) / +state+transition / full。

**为什么 P1 而非 P2**（从 89 号文的 P2 提升）：
- 审稿人会问："测试时切路只能说明训练好的模型在推理时依赖状态，不能说明状态在训练中是必要的"
- `T→Id` 那支证据文档自己标 `transition_margin_clean=false`（readout 收到训练外状态）
- **实测重训约 3 小时/arm**（8×H200）

**关键纪律（源自 anchor 消融教训）**：**跑之前必须预注册"某臂反而更好怎么写"**。

**数据**：复用 GreenEarthNet，同 manifest。

**预期风险**：某臂可能反而更好 → 需诚实报告并解释（"训练级 tradeoff"本身也是发现）。

### 4.5 P3：第二数据设置（期刊期待，但不是硬性要求）

**Codex 判断**：期刊实践上 2–3 个数据集；VegeDiff 证明单数据族也能过 TGRS，但那是有方法创新（扩散模型）的情况。

**三个候选**（按适配成本排序）：

#### 候选 A：EarthNet2021x 跨协议验证（最便宜）

**数据**：本机已展开，与 GreenEarthNet 属相近数据族。



**弱点**：**只能叫"跨协议验证"，不能包装成完全独立的数据集**——reviewer 会看出是同一数据族。

**适用场景**：TGRS（遥感审稿人理解这个价值）；TIP 可能不够。

#### 候选 B：DENETHOR（作物时序，德国，含时间 OOD）

**数据**：S1+S2+Planet + 作物标签，**自带时间 OOD split**（这是加分项）。

**公开性**：✅ 公开。



**为什么是作物数据集里的首选**：因为它有时间 OOD，与 GreenEarthNet ood-t 理念一致。

**适用场景**：期刊第二数据设置的标准选项。

#### 候选 C：DynamicEarthNet（未来语义变化，最贵但最独立）

**数据**：每日 Planet 影像 + 月度语义变化标注，75 AOI，2 年。

**公开性**：✅ 公开，本机已有 zip（525GB 未解压）。



**独特价值**：**唯一现成的"独立语义标注 + 时序"组合**，标签不源自 NDVI。

**适用场景**：TIP 强扩展（若坚持投 TIP）；TGRS 也认但不强求。

**决策规则**：
- 若投 TGRS：候选 A（EarthNet2021x）够用，性价比最高
- 若投 TIP 且时间允许：候选 C（DynamicEarthNet）
- 折中方案：候选 B（DENETHOR）

### 4.6 P4：Q3 深化（唯一剩下的强机制证据）

**内容**：不只报 84 对总体均值，报响应随严重度变化、按 LC 分层、lead-time 分解。

**为什么不是 P0/P1**：因为 Q3 已经成立，这是"做深"而非"填空洞"。

**数据**：`extreme` split 3,972 cube（本机有，需适配少一个 eobs 变量）。



### 4.7 P5：同协议基线（自跑 Contextformer 与 B4）

**内容**：同数据、同 scorer、同预算跑 Contextformer seed42 与 Phase-I B4。

**为什么 P5 而非更高**：主表数值目前引自 GreenEarthNet 论文，自跑是同口径但不改变主张。

**一个诚实前提**：Contextformer 是 context-only，无显式 z_t+T 路径。要在它上跑 Q2，需**先定义"无显式状态路径模型上 Q2 意味着什么"**——这需要新协议设计。

**权重**：Contextformer seed42 本机有；B4 本机有。

### 4.8 P6：状态复用下游（未来胁迫检测）

**内容**：冻结 TerraState 状态，训练小 head 做未来胁迫检测 / severity / onset。

**数据**：NDVI 阈值导出（本机有）+ **可选 SPEI/EDO 外部干旱指数参照**（见 §4.9）。

**六组对照**（缺一不成立，见 [[85]] §3.1）：
1. z_{t+h}（推进后状态）
2. z_t（context-only）
3. 同骨干 history feature
4. **history feature ⊕ 未来天气原始向量**（隔离"信息量"与"状态结构"）
5. 随机初始化
6. 完整预测输出导出特征（区分"可读出"与"含额外信息"）

**报告形式**：1% / 10% / 100% 标签比例的 label-efficiency 曲线；主指标 AUPRC（事件稀疏），辅以 AUROC/F1/Brier/ECE。

**为什么 P6**：不是"补什么都行"的下游，而是**唯一服务主线的下游**（证明状态不仅承载预测，还保留可迁移信息）。

### 4.9 P7（可选）：外部干旱指数提升标签独立性

**内容**：用 SPEI（全球格点）或欧洲干旱观测站 EDO 做外部参照，验证"预测的胁迫"与"独立气象学干旱指数"一致。

**数据**：
- SPEI：✅ 公开，全球格点，欧洲可用
- EDO Combined Drought Indicator：✅ 公开，欧洲，与 GreenEarthNet 同区域



**价值**：
- 把"派生事件评估"升级为"**与独立气象干旱指数交叉验证的未来胁迫预警**"
- TIP 侧增加应用可信度；ICLR 侧给"状态是否编码真实胁迫"提供非循环验证

**为什么标 P7 可选**：核心证据链（Q1/Q2/Q3）不依赖它；但若做了，标签独立性显著提升。

### 4.10 P8（若坚持投 TIP）：多光谱输出 + 图像质量指标

**内容**：改 readout 输出 RGB+NIR，改损失，重训，加 PSNR/SSIM/SAM/ERGAS/LPIPS。

**为什么是 P8**：**这是 TIP 路线的分水岭**——没有它，TIP 归属很难辩护。但若选 TGRS，**不需要**。



**决策规则**：
- 确定投 TGRS → **不做**
- 确定投 TIP → **必做**

### 4.11 期刊线实验优先级总结

```
P0  完整 OOD 矩阵（iid/ood-s/ood-st）          [共用层]
P1  四维分层（云/帧数/lead-time/LC）          [共用层]
P2  训练级 4-arm 消融                         [共用层]
P3  第二数据设置（EarthNet2021x / DENETHOR / DynamicEarthNet）
P4  Q3 深化（响应随严重度/LC/lead-time）
P5  同协议基线（Contextformer/B4 自跑）       [共用层]
P6  状态复用下游（未来胁迫，6 组对照）
P7  外部干旱指数参照（SPEI/EDO）           [可选]
P8  多光谱输出 + 图像质量指标               [仅 TIP]
```

**最小闭环**（TGRS）：P0 + P1 + P2 + P4 + P6（或 P3A EarthNet2021x）。

**TIP 闭环**：P0 + P1 + P2 + P3C（DynamicEarthNet）+ P6 + **P8**。

## 5. ICLR 线实验扩展（按重要性/优先级排序）

> **前提**：目标是 ICLR 2027 方法论文；你接受改模型。  
> **核心叙事**：不宣称从纯观测恢复真实因果，而是提出**多保真、干预感知的遥感预测状态世界模型**。

### 5.1 ICLR 路线的方法缺口（由负结果精确定位）

| 缺口 | 与负结果的对应 | 为什么 ICLR 需要 |
|---|---|---|
| **可组合转移** | Q4 不成立的根因 | 补上"递归状态转移"这一层；composition 进训练目标而非附加诊断 |
| **干预校准** | Q3 只证明"输出会变"，不证明"变得对不对" | ICLR 的四层证据阶梯中最关键缺口（见 §5.2） |
| **跨模型机制测量** | — | 证明"精度 ≠ 状态承载性"是普遍现象，不只是 TerraState 的个例 |

### 5.2 ICLR 的四层证据阶梯（当前只覆盖前两层的一部分）

| 层 | 内容 | TerraState 现状 |
|---|---|---|
| 1. 事实准确性 | 真实天气下预测是否准 | ✅ Q1 |
| 2. 响应性 | 改天气后输出是否变 | ✅ Q3（部分） |
| **3. 干预校准** | **变化方向/幅度/时间是否对应替代真值** | ❌ **最关键缺口** |
| 4. 干预外推 | 训练未覆盖驱动轨迹上是否仍正确 | ❌ |

### 5.3 I-P0：可干预状态结构 + 可组合转移（改模型）

**内容**：显式分离内生地表状态 z、静态条件 p、可替换外生驱动 u；支持逐步推进、中途换天气、分段组合。

**为什么 I-P0**：**这是 ICLR 线的地基**。不改模型，其他都是空中楼阁。

**目标**：T_{h1+h2}(z,u) ≈ T_{h2}(T_{h1}(z,u_{1:h1}), u_{h1:h1+h2}) 成为**方法与训练的一部分**。



**数据**：复用 GreenEarthNet。

### 5.4 I-P1：成对情景监督（过程模拟器 + 多保真对齐）

**内容**：引入过程模拟器提供"同初态、多驱动"的成对轨迹，使替代驱动输出不仅"会变"，而且能判断"变得对不对"。

**两条候选路线**：

#### 路线 A：植被线（WOFOST/PCSE + SCOPE，首选）

**模拟器**：
- WOFOST/PCSE：作物生长模型 → LAI / 生物量 / 土壤水分 / 物候
- SCOPE：辐射传输模型 → 状态 → 反射率

**数据**：
- 真实 EO：GreenEarthNet（继续用）
- 模拟器输出：同初态（土壤/品种/播种日），多未来天气 → 成对轨迹
- 公开性：WOFOST/PCSE ✅ 开源；SCOPE ✅ 开源



**优点**：**与现有天气-植被-EO 主线连续**，编码器与数据处理可复用。

#### 路线 B：洪水线（SFINCS，备选）

**模拟器**：SFINCS（快速洪水模拟） → 固定 DEM/糙率，换降雨/流量 → 淹没范围时序。

**数据**：
- 真实 EO：SpaceNet 8 / Sen1Floods11 / WorldFloods（❌ 本机无）
- 模拟器输出：同地形，多降雨情景 → 淹没演化

**公开性**：SFINCS ✅ 开源；洪水数据集 ✅ 公开。



**优点**：干预信号最清楚、易可视化。

**决策规则**：首选路线 A（植被），除非有外部洪水合作方提供数据管线。

### 5.5 I-P2：跨模型机制测量（证明"精度 ≠ 状态承载性"）

**内容**：在 Contextformer / Phase-I B4 / TerraState 上测同一套状态承载性指标与天气响应保真度，看精度排序与机制排序是否一致。

**为什么 I-P2**：
- ICLR 候选 A 叙事（"精度与状态承载性可解耦"）的核心证据
- 只在 TerraState 自己身上测，说服力有限

**一个诚实前提**：Contextformer 无显式状态路径，需先定义协议。

**数据**：复用 GreenEarthNet。



### 5.6 I-P3：干预外推评测（训练未见驱动强度/组合）

**内容**：在训练未覆盖的 forcing 强度（如双倍降雨）、未见组合（如热+湿）上测响应是否仍与模拟器一致。

**为什么 I-P3**：ICLR 四层阶梯的第 4 层；证明不只是"记住训练见过的情景"。

**数据**：模拟器构造 OOD forcing。

### 5.7 I-P4：真实干预外部检查（可选）

**内容**：用真实随机干旱处理实验（DroughtNet / IDE）做外部合理性检查。

**数据**：
- DroughtNet：✅ 公开，全球多站点随机干旱处理
- IDE（国际干旱实验）：✅ 公开



**为什么 I-P4 可选**：ICLR 不要求真实因果验证，模拟器监督 + 外推已够；但若做了，是强加分项。

### 5.8 ICLR 线实验优先级总结

```
[共用层] P0/P1/P2/P5（完整 OOD 矩阵 + 四维分层 + 训练级消融 + 同协议基线）
I-P0  可干预结构 + 可组合转移（改模型）       [地基]
I-P1  成对情景监督（WOFOST/PCSE+SCOPE）      [核心]
I-P2  跨模型机制测量（证明精度≠机制）       [核心]
I-P3  干预外推评测（OOD forcing）
I-P4  真实干预外部检查（DroughtNet/IDE）  [可选]
```

**最小闭环**：共用层 + I-P0 + I-P1 + I-P2。

## 7. 执行排期与决策规则

### 7.1 总体节奏

```
S1 基准点确认（阻塞项）
S2 偏移矩阵 + S6 效率 + S8 同协议基线
S3 四维分层 + S4 Q3 深化 + S5 状态诊断
S7 训练级消融
──────────── 分叉决策点 ────────────
起   期刊线：P3→P4→P6→(P7)→(P8)
            或
            ICLR 线：I-P0→I-P1→I-P2→I-P3
```

### 7.2 分叉决策规则

**在，按实测结果决定，而非按偏好**：

| 若实测发现…… | 则…… |
|---|---|
| S5+S8 发现**精度与状态承载性解耦**（Contextformer 精度高但状态承载性低） | 走 **ICLR 候选 A/B**（强洞察） |
| 没发现解耦（各模型机制与精度同序） | 洞察不成立，走**期刊线** |
| 愿意投入 3–6 个月改模型 + 接模拟器 | 走 **ICLR 候选 C**（方法贡献最实） |
| 时间紧、要稳 | 走**期刊线**，并认真考虑 **TGRS 而非 TIP** |

**一个补充判断**：以当前形态（NDVI 单通道 + 证据协议 + 主表第六），**ICLR 匹配度高于 TIP**，而 **TGRS 匹配度高于两者**。
