# A14B 第一数据集实验：实现、测试、统计与图表验收

日期：2026-09-07。先读 [A14](./A14_训练端执行总纲与监督契约.md) 的权限和安全规则。本文件包含计划接口和计划文件名，**未注明已有的均不是已经实现的命令**。执行端必须先读现有 CLI 的 `--help`，不能把此文伪代码直接当作可运行脚本。

## 1. 总体技术策略

先用既有 C0R/C1 权重完成新评估，尽量复用现有模型和 scorer；只添加薄接口、可追溯统计与测试，不先重构网络。科学效应经过既有权重检验后，再进入额外种子及训练对照。

建议新增模块按现有项目组织，不强制新目录：runtime adapter（运行状态适配器）、continuation evaluator（共同后缀评测器）、table collector（表格汇总器）、figure exporter（绘图数据导出器）。新增接口不得改变旧 checkpoint 参数名或旧预测默认行为。

## 4. G2a：运行状态接口

### 4.1 推荐接口语义（计划，不是现有 API 保证）

```python
state = initialize(history_batch)  # 只调用一次历史编码器
state_b = advance(state_a, weather_segment, end_offset=b)
prediction_b = decode(state_b)     # 使用绝对 b 的 prior
state_copy = branch(state_b)       # 深拷贝动态可变部分
save_state(state_b, destination)
restored = load_state(destination, expected_model_hash=...)
```

state 必须保存：动态 z、完整 prior、geo/静态条件、offset、t0 或足以恢复日期的元数据、空间 patch 与 batch 映射、dtype、schema、模型及数据合同标识、有效 horizon。是否存天气由接口决定，但不能重复或漏消费天气。

`advance` 输入只允许从当前 offset 到 end_offset 的天气段；若接收完整天气轴，必须由明确索引切片，且测试验证。禁止依赖未序列化的全局变量、闭包、原始 batch 或原进程缓存。

### 4.2 当前模型最易出错处

`endpoint_prediction()` 取 `prior[:, sum(partition)-1]`，只适合从初始化起点计数。中间恢复后继续 10 步到绝对第 20 步时，不能继续取 prior 第 10 步。适配器应显式保留绝对 offset。

`segment_states()` 的 time embedding 使用每段跨度，不是累计时距。包装时不要为了“更合理”悄悄换成累计时距，否则已经改变模型而非添加运行接口。

天气 GRU 在每个片段内编码，不能把同一条日天气重复送两次，也不能把切分后的第 2 段从 0 再取一次。当前方法不保存跨段 GRU hidden state；如要改此点，属于新模型变体，需另行审批。

超过有限 prior 的窗口应显式报错，不循环 prior、补零 prior 或悄悄重新编码。输入未来 GT 应只存在 evaluator，不进入 runtime state。

### 4.3 必须通过的合成单元测试

| 测试 | 构造与断言 | 失败意味着什么 |
|---|---|---|
| prior 绝对索引 | prior 第 h 帧设为可辨认常数；10→20 必取第 20 帧 | 时间偏移错误 |
| 天气消费 | 每个时刻天气设为唯一标识；两段拼接恰好覆盖原路径一次 | 漏读/重复/错序 |
| 跨度条件 | spy 记录 T 每次接收的跨度等于段长 | 包装改变了训练语义 |
| 单段等价 | adapter 一段输出等于旧 direct 实现 | 新接口行为回归 |
| 两段等价 | adapter 两段输出等于旧 composed 实现 | 新接口行为回归 |
| 分支隔离 | 修改分支 A 不改变 B 与原 state | 张量别名或原位污染 |
| 保存恢复 | 同一设备精度下内存连续与恢复结果 allclose | 序列化丢失运行信息 |
| 模型身份 | 错 checkpoint/schema 加载明确失败 | 跨模型状态误用 |
| 越界 | 非正跨度、天气不足、超过 horizon 立即失败 | 静默错预测 |
| 无重编码 | spy 统计 initialize 后 advance/decode 编码调用为零 | 续推偷读历史 |
| 无未来观测泄漏 | 固定历史/天气，改变仅 evaluator 持有的 GT，预测不变 | 数据管线泄漏 |
| 权重不变 | 推理前后权重 hash 相同 | 干预未恢复或误训练 |

FP32 同设备接口测试可先采用 `atol=1e-6, rtol=1e-5`，记录最大误差。不同设备/混合精度另设事先固定容差，不要求跨硬件 bit-exact；不为让测试过而看结果后反复放宽。

跨进程恢复测试必须启动一个不持有历史 batch 的新进程：只加载模型、状态文件和后续天气，再产生预测。训练 checkpoint 的 optimizer/RNG 恢复测试不计入这一项。

## 5. G2b：共同后缀核心实验

### 5.1 需要区分的三条路径

同一 history、同一完整 weather 和同一 GT：

```text
参考 D20：S0 -> T[0:20] -> y20
路径 A ：S0 -> T[0:10] -> SA10 -> T[10:20] -> yA20
路径 B ：S0 -> T[0:5] -> T[5:10] -> SB10 -> T[10:20] -> yB20
```

主要比较 A/B 的共同后缀，不把 D20/A 的端点比较冒充新增后缀实验。三者都报告对事实 GT 的误差。

先做 `b=10,c=20`。扩展 `b=5,c=15`、`b=15,c=20` 等需要确认分段在当前时间嵌入/天气长度范围内，且有充足有效标签。每个中间时刻至少一个训练中出现的前缀分段和一个历史留出前缀分段。

旧分段清单：

```text
train: 10->[10],[5,5],[5,3,2]
       15->[15],[7,8],[7,4,4]
       20->[20],[10,10],[10,5,5],[5,5,5,5]
heldout: 10->[3,7],[6,4],[2,3,5]
         15->[4,11],[3,5,7]
         20->[8,12],[2,18],[2,6,12],[1,4,6,9]
```

以正式 manifest 为准并记录 SHA，不能因代码默认值相同就跳过核对。已经看过结果的 heldout 是历史留出，不是本轮调参后的全新盲测。

### 5.2 后续轨迹的生成方法

主方案：分别从 SA_b/SB_b 独立 branch，对每个 k=1..c-b 使用共同天气 `u[b:b+k]` 直接推进 k 步并读出 `prior[b+k]`。这衡量同一中间状态对多个未来读出的预测能力，不修改原状态。

辅助方案：两边都固定步长逐步推进，形成真正连续 rollout。两种方案分别标记 `suffix_query_mode=direct_queries/fixed_step_rollout`，不得混成一条曲线。

必须同时给完整后续窗口误差和终点误差。不能只看最后一帧，也不能只算 A/B 输出差距。

### 5.3 输出字段

每条样本、每个 seed、每个前缀路径对、每个后缀模式保存：cube_id、tile_id、日期、b/c、partition_A/B、有效像素计数、GT 的 sum/sum_sq、各路径 SSE、A/B 输出差平方和、原始中间状态距离、各预测的均值/标准差、是否 finite。

聚合产物至少包括：
- A/B/D20 各自的 RMSE_pool、R²_pool；
- 后缀 A/B 输出差距与相对量级；
- C1 相对 C0R 的路径退化变化及配对 CI；
- 中间状态距离与后缀输出差距的分布；
- 各组合有效 cubes、有效 pixels、空间 clusters；
- 真实无效与工程失败分开计数。

### 5.4 替代后缀天气的边界

在另一条预定义合理天气后缀下比较 A/B 是否仍相容，可增强功能等价检验。但该后缀没有本样本对应真实未来，不能计算它相对原 GT 的“反事实准确率”。主事实后缀仍必须与 GT 比较。

### 5.5 执行阶梯

1. 合成测试：仅验证接口和公式。
2. 2–4 个真实 cubes：两模型完整加载，所有字段可出数；这是 smoke。
3. 小型空间分层 pilot：只使用预定开发/验证范围，预估时间/空间、检查资格与 CI 可计算性。
4. 冻结正式样本和协议后运行正式范围。可先用历史 476 cubes 复现关联，再扩到预先选定的第一数据四 split 机制子集；样本量与资源预算经确认，不能随意以首 N 个文件代替代表性样本。
5. 单种子正式评测完成后审阅是否值得多种子训练。不能因 pilot 好看直接宣称四 split 成立。

## 6. G2b：中间状态功能替换

固定受试样本的 prior、geo、offset 和后续天气，仅改动态状态。

| 条件 | 具体实现 | 能回答的问题 | 必须说明的混杂 |
|---|---|---|---|
| full | 正常推演到 b 的 z_b | 参考 | 无 |
| reset-z0 | 用自身初始 z0 替代 z_b | 已推进状态是否带来后续信息 | 状态时刻分布偏移 |
| matched donor | 同模型另一匹配样本的同刻 z_b | 状态是否有样本相关信息 | 与本样本 prior/geo 不匹配 |
| alternate-prefix | 同一历史在替代前缀天气下产生 z_b | 过去 forcing 记忆是否影响后续 | 替代路径无真实物理标签 |
| prior-only | 后续关闭动态读出 | 状态支路是否承担后续输出 | 去掉整个支路不是细粒度记忆定位 |

donor 在同一 checkpoint 内产生，按季节、初始观测和可用地类匹配，不能用测试未来误差挑选。保存 donor ID、匹配距离和重用次数。避免跨 C0R/C1 互换潜变量。

对于 alternate-prefix，保持本样本 history/geo 不变，只替换前缀天气；回到相同事实后缀后观察预测差异。它检验模型的条件历史依赖，不证明真实世界的天气因果效应。

输出 `ΔMSE = MSE_intervention - MSE_full` 与配对空间聚类 CI，报告胜/负样本比例、效应分布，不以少数地图代替整体统计。Table 4B 汇总；Fig. 7 显示过程。

## 8. G4：多种子与训练机制对照

### 8.1 主对照 C0R/C1

同一 parent checkpoint、模型参数、初始权重、数据顺序、标签时刻、optimizer、学习率、有效 batch、验证选择规则。两臂都保留直接轨迹监督，唯一主差分是额外端点损失是否经过递归分段。

记录两臂实际 RNG 消耗、端点采样计划、partition_drawn 与 partition_used；不能因为 direct 不用递归分段就少抽一次随机数导致训练样本不同。

如果多个种子共享同一预训练 parent，准确描述为“共享预训练初始化上的多种子后续训练”，不声称整个模型从头独立三次。新种子不是把同一权重重新评估三次。

### 8.2 固定步长基线

在同一状态/读出结构中，以固定基本步长递归推进，监督时刻与事实标签尽可能匹配。明确其没有任意跨度一步跳转能力，但暂停后继续相同循环的相容性是天然性质。

公平比较：相同目标查询的真实误差、转移调用次数、墙钟时间及状态复用成本。不能把不支持的跨度接口当成错误记零，也不能将“暂停保持一致”包装成本方法独有优势。

### 8.3 简单输出一致性对照

保留 C0R 事实监督，增加 direct/composed 预测一致性正则，作为“普通约束是否足够”的直接对照。损失形式可为在固定有效区域的输出 MSE，必须事先固定 reduction、梯度是否双边、mask、λ 候选。

只在训练/验证集选 λ，所有 λ 试验和预算登记；不要根据 Q4 测试集结果搜索到最好再叫确认实验。为避免状态不唯一带来的额外假设，输出一致性优先；潜空间一致性只作条件探索。

C1+一致性不是默认最终模型。若要升级，给新模型 ID，重新跑核心对照，不把新增损失归功于原 C1。

### 8.4 计算量匹配

同更新 C0R/C1 是标签与优化步数控制，不是计算预算控制。记录训练期 encoder、天气编码、T、readout 调用数和 GPU 时间。

增加 C0R 计算匹配臂时，选择并公开预算准则（如累计估算训练 FLOPs），记录增加更新造成的样本暴露次数差异。没有一种匹配同时控制所有因素，必须保留同更新主对照与计算匹配辅助对照，不能混称单变量。

### 8.5 第二编码器

在第一数据核心结论成立后，可做另一个成熟视觉编码器下 direct/recursive 配对。只更换 C1 编码器而无配对 direct，不能证明机制跨架构普适。不要在方法未稳前换成大 ViT 或扩散模型以追求名称新颖。

此项根据核心贡献风险与预算启动，不阻塞 G1–G3。更换编码器不是第二数据适配的必需前提。

## 9. G5：天气对照与近邻基线

Q2 不要求所有外部模型，因为 prior-only 干预不是通用接口。Q3 选 C1、C0R、Contextformer 或已确认天气感知强基线，在同一 manifest、同天气替换和损失窗口下比较。

除热旱子集，增加预先定义的正常/总体范围；按季节/植被类型分层作为解释，报告样本数。总体与极端层结果分开，不用极端样本效应填总体行。

天气顺序扰动需明确是在日频还是模型五日步上打乱，是否保持多变量联合关系。实际天气并非所有端点都显著优于顺序扰动；各控制分别报告，不能只报告多个破坏控制平均后的有利门。

近邻强基线优先调研 VegeDiff 等任务匹配工作。公开权重可同协议评测则先评；没有权重时提出训练预算，不抄文献分数。VegSim 若只输出 cube 平均 NDVI，不强行伪造其像素图；可在另一个明确的空间均值任务上比较，但不能替代密集图像主表。

为概率模型固定采样数和聚合策略，计入采样成本。不能 best-of-N 看 GT 后挑最优样本与确定性单输出比较。

## 10. 统计合同

### 10.1 共同集合与聚合

每项配对比较使用相同 cube、相同目标时刻、相同有效像素 mask。资格由 GT/观测与预定规则决定，不由哪一个模型误差更低决定。工程预测 NaN 属失败，不得通过删除样本提高结果。

RMSE_pool：合并 SSE 和 n 再开根号。R²_pool：合并 n、sum_y、sum_y2，令 `SST=sum_y2-sum_y^2/n`，再算 `1-SSE/SST`。SST=0 时记未定义，不加随意小常数造成有利分数。

官方指标另走官方层次汇总；主表 native 与机制 pooled 不混用。逐时距误差与整窗口误差分别命名。

### 10.2 置信区间

主要新 CI 按空间 tile/预定地理组配对重采样，同一次抽样对所有模型使用相同组；建议 2,000 次 bootstrap，固定统计随机种子。合并充分统计量后重算非线性指标，不能直接平均每组 RMSE 代替 pooled bootstrap。

训练 seed 间离散度与测试样本抽样 CI 分列。三种子可报 mean±std，不能因样本像素很多就把单模型训练不确定性说成很小。跨种子聚合时明确层次设计，不把同一 cube 的三个模型输出当独立样本。

### 10.3 阈值与确认

既有 Q4 修正结果完整保留。新共同后缀实验先定义效应量、报告曲线与 CI，不强制沿用旧 G_abs 的一组门。

若要主张非劣，需要事先明确容忍幅度及其领域/误差意义，并在验证阶段冻结。不能把旧门的 5% 从 MSE 偷换到 RMSE，也不能由当前测试结果反推最容易通过的阈值。

多个端点/分段的主结论提前指定主比较，其余标探索性；必要时使用同时区间或多重比较控制，不以任意一个显著点代替整体稳定。

## 11. G6：效率、FLOPs 与可复用状态

固定硬件、软件、dtype、batch、输入 shape、horizon、线程、GPU 同步方式和 warm-up。计时前后同步 GPU，至少报告重复次数、中位数和波动范围；共享服务器竞争严重时不出正式计时结论。

分开测量：历史初始化、天气编码+T、读出、完整预测、状态序列化到磁盘、加载+设备搬运、分支复制和多分支总调用。保存和加载只测可信自有状态文件，不任意反序列化未知来源。

场景 A：单次固定预测窗口。场景 B：同一历史多个时距查询。场景 C：同一中间状态 B=1/2/4/8 条天气后缀。每个场景所有模型交付相同目标时刻和输出数量。

基线也允许合理缓存历史编码；冷启动与热缓存分别报告。固定步长模型允许自然复用 hidden state，不能要求其每个查询都从头算。

FLOPs 统计注明工具版本、不支持算子和 MACs→FLOPs 约定；无法准确统计时报告估算范围与实测时间，不能填一个无解释的整数。参数数目从模型直接统计，不能仅用文件大小推算。

state size 包含 prior、z、geo、时间与映射元数据；分别报张量字节、序列化文件大小。若共享只读 prior，则同时报每样本基础存储与每新增分支增量，不能只报增量冒充总大小。

## 12. 代码交付与回归测试

每个手工变更尽量单一用途；不改训练默认损失、不动旧 scorer、不重命名已冻结结果。新增 CLI 支持 `--dry-run`、显式 manifest、显式 output-dir 和预算限制；不存在这些选项时先实现并测试，再写使用命令。

测试覆盖至少包括：路径越界、空/非法 partition、索引与天气切片、跨进程恢复、分支别名、模型身份、未来 GT 隔离、单/两段旧输出回归、全无效 mask、常量 GT、bootstrap 可复现、collector 缺字段报错和原文件未变。

重任务启动前，输出命令解析后的模型/数据路径、样本数和预计产物大小；dry-run 不实例化数据下载器。不能在测试 collection/import 时触发下载、训练或输出大文件。

## 14. 停止、修正与最终解释

共同后缀不足时先查 offset、天气单位、prior、mask、权重和 eval 模式。若实现无误，按科学结果报告，再考虑新的分段训练分布、输出一致性或状态转移结构。不能自动加损失后把旧 C1 的名字与成绩混用。

state swap 无明显影响不必立即否定所有世界模型身份，但会削弱“中间状态携带独特后续信息”的主张。fixed-step 或简单正则全面相当/更好，会削弱当前方法独特性；此时要回到方法与实际收益，而不是堆图。

本文件的目标不是强行制造无懈可击的正结果，而是让第一数据集上的每一个核心主张有正确、完整、可复核的证据，并让缺口尽早暴露。
