## 0. 先看这里：一条命令就够

```bash
git pull                                    # 先同步到最新
bash tools/setup_new_machine.sh             # 全自动，可重复运行
```

这一条命令做完 §1–§5 的全部内容：拉 LFS 权重并校验 SHA、建 venv 装依赖、下官方基线权重、
clone 两个上游只读仓库、下载 5 个数据 split 并逐个核对数量、最后真正加载一次模型自检。

**每个阶段都会自我跳过。** 断在哪都不用管，直接重跑，已完成的会显示"已就绪，跳过"。
失败时它会打印具体该怎么办，然后停下，不会在坏地基上继续。

可选参数：`bash tools/setup_new_machine.sh /你的/数据目录`
（默认 `<repo>/../TrainData/EarthNet2021/earthnet2021x`）

### 已知会卡住的地方，脚本已经替你处理

| 现象 | 脚本的处理 |
|---|---|
| Zenodo 2.3GB 包下到 200–900MB 就断，解压报 `End-of-central-directory signature not found` | 那不是文件损坏，是没下完。`tools/fetch_zenodo_baselines.sh` 会**断点续传最多 40 轮**并校验 SHA |
| 没有 `aria2c`，装不上 | 数据下载脚本自动**退回 curl**（慢些，同样断点续传） |
| 没有 `python3-venv` | 自动退回 `virtualenv` |
| `git clone` 后权重是 133 字节 | 那是 LFS 指针。脚本会检测并告诉你先装 git-lfs 再 `git lfs pull` |

### 最重要的一条

**官方基线权重（Zenodo 那个 2.3GB）是可选的。** 它只用于**重跑** E1 基线，
而 E1 已经在上一台机器上全部跑完（48/48），结果 JSON 全在仓库里。
下不下来都不影响任何其他工作 —— 脚本会跳过它继续往下走，不当失败处理。

## 6. 已知的坑（动手前必读，每条都实际踩过）

**① conda 的 CA bundle 是旧的。** Python 会间歇性对这个 S3 报
`CERTIFICATE_VERIFY_FAILED: certificate has expired`，而**服务器证书其实有效**
（2025-12-17 → 2026-12-17），`curl` 每次都成功。传 `SSL_CERT_FILE` 或显式
`ssl.create_default_context(cafile=...)` **都不够**，部分集群节点仍失败。
→ 列举用 curl、传输用 aria2c（都走系统 bundle）。脚本已这么做。

**② 不要走本地代理。** `s3.bgc-jena.mpg.de` 直连可达，代理只会增加失败模式。

**③ 并发别开大。** 16 并发被限流打出 2004 个 HTTP 503。4 并发 / 每服务器 2 连接稳定。

**④ 列举会静默截断。** bash 分页循环里内嵌的 python 只要有一页解析失败就退出非零 →
token 变空 → 循环 break → 该 split 被当成"下完了"。实测 `ood-s_chopped` 被列成
4000/10536、`ood-st_chopped` 列成 0/7024，**全程无报错**。
→ 脚本已加**逐 split 对象数断言**，对不上直接中止。

**⑤ 官方 pixelwise 脚本用 `np.NaN`**（NumPy 2.0 已移除）。用
`eval/run_pixelwise_baseline.py` 包一层，在进程内恢复别名，**不改上游文件**。

**⑥ 官方 yaml 少三个超参**，需按上游 argparse 默认值补：`spatial_shuffle=False`、
`use_weather=True`，以及 ConvLSTM 的 `global_step`（传大值让 teacher forcing 衰减到 0，
这是推理时的正确行为）。`export_emp_baseline_predictions.py` 已处理。

**⑦ 评分器是 fail-closed 的** —— 预测文件不齐就拒绝打分，所以没法用少量样本测评分链路。
先跑完整导出再评分。

**⑧ 中间产物极占盘。** 逐 cube 预测 + score parquet 在本机累计约 **471 GB**。
结论只在几 KB 的 JSON 里，表定稿后可整批删。新机器留足空间或及时清理。

**⑨ 别用 `pkill -f` 内联清理任务** —— 模式会匹配到调用方自己的命令行，
把 shell 一起杀掉（本机发生过三次）。用仓库里的 `reap_e1_orphans.sh`。

## 7. 装完之后能跑什么

```bash
cd <repo>/terrastate
D=/path/to/TrainData/EarthNet2021/earthnet2021x

# E1 主表：48 个基线配置（4 模型 × 3 seeds × 4 splits）
bash run_e1_queue.sh 8 4,5,6,7 <configs>     # 已完成的自动跳过
python collect_e1_table.py                    # 机械生成 A08 主表

# C1 的 Q1/Q2（补某个 split）
bash run_c1_rest_gpu.sh

# C1 的 Q3（84 对极端样本，冻结协议已在仓库内）
python eval/extreme_state_audit.py \
  --protocol-dir artifacts/protocols/extreme_audit_oodt_v1 \
  --dataset-root "$D" --data-dir "$D/ood-t_chopped" \
  --ckpt-exclusive ops/candidate_c_nightly/*/formal/run_c1_*/checkpoint_main.pt \
  --device cuda --evidence-role final --dump-per-cube --output-dir <out>
```

**GPU 不是必需**——所有评测都能在 CPU 上跑（Q1/Q2/Q3 最初就是纯 CPU 完成的），
只是慢。实测瓶颈是 NetCDF I/O 与 CPU 评分，不是 GPU 算力，
所以给评测加卡的收益远小于预期。
