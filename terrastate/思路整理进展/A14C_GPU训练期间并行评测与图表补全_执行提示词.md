评测 GPU 隔离：一个进程用 `CUDA_VISIBLE_DEVICES=0`，另一个用 `CUDA_VISIBLE_DEVICES=1`，各自进程内通常是 `cuda:0`；实际卡号先核对，不混用物理和逻辑索引。不使用 DDP，不全卡自动发现，不改变训练进程环境。

先单评测进程 `batch_size=1, num_workers=0` 跑少量真实样本，再决定是否启用第二进程。每个评测进程 CPU 线程初始限制为 1–2，总计先不超过 4；统计和绘图也限线程。记录 RAM、磁盘 I/O 和资源余量，必要时串行，禁止大规模 worker 抢占训练数据加载资源。

评测使用 `eval()` 与 `inference_mode/no_grad`。沿用冻结 scorer 与推理精度；确需混合精度时先验证与原精度误差，单独标记，不能悄悄改变正式指标。

只读测磁盘，并给正在训练的后续 checkpoint 和临时保存预留空间。并行评测默认新增输出预算 2GiB、额外空闲底线至少 10GiB；还需扣除训练预计剩余 checkpoint 峰值占用，不能将这两项预留重复使用。预算不够时先只汇总小型 JSON/CSV。禁止缓存全量多路径 NetCDF。

固定配置 TMPDIR/TMP/TEMP、MPLCONFIGDIR、XDG_CACHE_HOME、PYTHONPYCACHEPREFIX、Torch/HF/CUDA 等实际使用缓存到根内。禁止因为缺图形环境而安装全局软件。

不读取正在写入的 seed 27 checkpoint 作推理，不监控每个新 checkpoint 并自动评测，不改其选择策略。若并行工作造成资源压力，只降低/停止本轮评测进程，不动训练。

### 十、统计、资格与防重复计算

- 官方 r²_LC 与 R²_pool 分开，RMSE_LC 与 RMSE_pool 分开；历史“平均 RMSE”的小样本结果未经核对不能改名 pooled。
- mask 对每组比较一致；全云/目标无效是数据资格问题，模型 NaN 是工程失败，二者分开。缺数值填 null/空白并给理由，不填零。
- 新 CI 采用 A14B 的地理组配对 bootstrap，保存 seed 和聚合方案。多个训练种子的方差与空间抽样 CI 不是一回事。
- 缓存键包含 checkpoint SHA、代码/配置 hash、manifest、路径/天气干预、目标窗口、mask 和 metric version。不同 key 不共用结果。
- 小 JSON/CSV 的统计汇总可反复计算；大数据推理先查是否已有完全匹配产物。初始化状态在同一模型同一样本内合理复用，各分支不原位污染。
- 流式保存充分统计量和少量可视化；一批完成后写完整 chunk/状态，支持断点续评，不重新推理已经完整验收的 chunk。
- 对需要大量额外空间/长时间运行的范围，先报告基于 smoke 实测的预算，再请求该范围授权。已授权 GPU 0/1 上的预算内小规模评测不用反复问同一问题。
