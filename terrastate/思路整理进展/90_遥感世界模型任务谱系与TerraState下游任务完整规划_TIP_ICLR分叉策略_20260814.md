## §1 必须先理清的概念边界：基础模型 vs 世界模型

### 1.1 为什么这个区分如此重要

你的直觉——**"洪水检测、地表变化、城市扩张更像是基础大模型要做的东西"**——是完全正确的。这个判断比它看起来更重要，因为它直接决定了：

1. **哪些下游任务值得做**（哪些能支持主张、哪些会稀释叙事）
2. **实验数量是不是越多越好**（基础模型是、世界模型不是）
3. **审稿人会用什么标准评判你**（广度 vs 机制深度）

但这个边界经常被混淆，原因有三：

| 混淆来源 | 表现 | 后果 |
|---|---|---|
| **名称相似** | "洪水检测"可以是基础模型任务，也可以是世界模型任务 | 看到任务名就以为知道它属于哪边 |
| **模型可以两者都是** | 一个模型可以既是基础模型又是世界模型 | 误以为必须同时证明两边 |
| **论文不总是明确标注** | 很多论文自称"world model"但其实在做表征迁移 | 被误导去模仿不对口的实验设计 |

### 1.2 两者的本质区别（不在任务名，在被证明的命题）

| 维度 | 遥感基础模型 (Foundation Model) | 遥感世界模型 (World Model) |
|---|---|---|
| **核心命题** | 我学到的**表征**可以迁移到很多任务 | 我学到的**状态 + 转移**可以在驱动下推演未来 |
| **输入是否含未来驱动** | 通常不含（或不依赖） | **必须含**（天气/动作/强迫） |
| **输出时间指向** | 当前帧的语义/类别 | **未来**的状态或观测 |
| **证据形式** | 多任务 × 多数据集 × 少样本迁移曲线 | 预测精度 + **状态承载** + **驱动响应** + 分布偏移 |
| **典型代表论文** | SatMAE / Scale-MAE / CROMA / SkySense / Prithvi | Dreamer 系 / Genie / EO-WM / VegSim / **TerraState** |
| **任务多 ⇒ 更强？** | **是**，广度本身就是主张 | **否**，广度不能替代机制证据 |
| **主表不第一是否致命** | 较严重（要证明可用性） | 较轻（若机制证据强） |

**最关键的一条判据（可以直接拿去筛任务）**：

> 一个任务属于世界模型下游，当且仅当**去掉未来驱动后这个任务就做不成了**。

### 1.3 同一个任务名可以两边都属于（区别只在时间指向）

这是最容易被忽视的一点。看下表：

| 任务名 | 静态版（→ 基础模型下游） | 未来版（→ 世界模型下游） |
|---|---|---|
| **洪水** | 洪水后影像 → 当前淹没范围 | 洪水前状态 + **未来降雨** → **未来**淹没范围 |
| **地表变化** | 两期影像 → 已发生的变化掩膜 | 当前状态 + **未来天气** → **未来**变化掩膜 |
| **城市扩张** | 多期影像 → 已发生的扩张 | 当前状态 + 规划/驱动 → **未来**扩张（驱动难获取） |
| **作物** | 已观测季节 → 当前作物类型 | 历史 + **未来天气** → **未来**胁迫/物候/产量 |

**静态洪水分割**：
- 输入：洪水后的 SAR/光学影像
- 输出：当前被淹区域
- 去掉未来驱动还能做吗？**能**（输入里根本没有未来驱动）
- 证明了什么？当前场景语义理解、表征迁移
- 结论：**基础模型下游，不是世界模型下游**

**未来洪水范围预测**：
- 输入：洪水前状态 + **未来降雨/水文驱动**
- 输出：**未来**被淹区域
- 去掉未来驱动还能做吗？**不能**（没有未来降雨就无从预测未来淹没）
- 证明了什么？状态与驱动能模拟未来事件
- 结论：**世界模型下游，概念上极佳**

**关键推论（回答你的核心疑惑）**：

1. ✅ 你的直觉是对的：**静态洪水检测、地表变化、城市扩张更像基础大模型任务**
2. ❌ TerraState 不做这些**不是缺陷**，EO-WM 和 VegSim 也都没做
3. ⚠️ 如果一定要在"灾害"方向做，**未来洪水范围预测**概念上极佳，但它几乎是第二篇论文的体量（需要洪水事件时序标注、与 minicube 对齐的降雨驱动、水文合理的评测协议）

### 1.4 一个模型可以既是基础模型又是世界模型吗？

**可以，但需要同时证明两边**：

| 如果主张 | 必须证明 | 典型证据 |
|---|---|---|
| 只是基础模型 | 表征可迁移 | 多任务、多数据集、少样本、线性探测 |
| 只是世界模型 | 状态 + 转移能推演未来 | Q1 预测 + Q2 状态承载 + Q3 驱动响应 |
| **既是基础又是世界** | **两边都要** | 上述全部 + 证明两者不冲突 |

**TerraState 当前是哪一种？**

目前是**纯世界模型**（有 Q1/Q2/Q3，没有多任务迁移证据）。

**要不要变成"既是基础又是世界"？**

- ✅ 如果有充分时间和算力，这是长期愿景（73 号文的 ObsWorld 统一路线）
- ❌ 如果目标是近期投稿（TIP 或 ICLR），**不要**——两边都做会稀释主线，而且基础模型那边需要的实验量（7–16 个数据集）远超世界模型
- 🔶 可以做一个**轻量的辅助实验**：冻结状态的低样本探针，证明"状态不仅承载预测，也保留可迁移语义"——但这仍然是服务世界模型主张的，不是要把论文变成基础模型论文

## §2 遥感世界模型的六大任务类别

89 号文已给出 A–F 六分类，这里在其基础上补上你真正关心的：**每类的典型任务形式、哪一类是主流、我们在哪一格**。

### 2.1 六分类完整表

| 类别 | 一句话定义 | 典型任务形式 | 主流程度 | 代表工作 | TerraState 位置 |
|---|---|---|---|---|---|
| **A. 空间外推与世界补全** | 中心影像 + 方向 → 邻接未观测区域 | 中心 tile → 上下左右邻接 tile；缺失空间区域补全；大视野空间一致生成 | 新兴（2025 年才起） | RemoteBAGEL / RSWISE | ❌ 不做 |
| **B. 时间预测与动力学推进** | 历史 + 未来驱动 → 未来地表 | 多光谱影像/视频预测；NDVI/植被轨迹预测；降水/海温/大气物理场预测；长时域 rollout | **绝对主流** | EO-WM / VegSim / ViT-Koop / ContextFormer | ✅ **主线在此** |
| **C. 替代驱动下的情景模拟** | 换掉未来驱动 → 看轨迹如何变 | 情景条件模拟；受控 forcing 干预；替代强迫轨迹滚动 | 主流的第二支柱 | VegSim 四情景 / EO-WM Extreme Summer / TerraState Q3 | ✅ **Q3 在此** |
| **D. 部分观测下的状态估计** | 云遮挡/缺帧下恢复潜在状态 | 云补全；S1↔S2 跨模态补全；缺测插值；观测条件与地表状态分离 | 成熟但常被算作表征学习 | 云补全系列 / Stage1–1.5 | 🔶 **有资产未兑现** |
| **E. 语义世界理解与未来事件** | 不只生成像素，预测事件/风险 | 未来植被胁迫/干旱风险/洪水范围；未来土地覆盖变化；时空变化问答 | 上升期 | RS-WorldModel | 🔶 **最佳扩展方向** |
| **F. 不确定性与多种可能未来** | 输出分布而非单张平均图 | 分位数预测；CRPS；coverage；spread–skill | 气象侧成熟，EO 侧刚起 | VegSim 概率输出 / GenCast 类 | ❌ 当前确定性模型 |

### 2.2 三个结论（对应你的"串起来内化"需求）

**结论 1：你的原始三分类覆盖了 A、B、C，漏掉了 D、E、F。**

你说的"预测当前图像上下左右的未观测景象 / 预测未来会发生什么 / 改变未来天气预测另一种可能结果"分别对应 A、B、C。漏掉的三类中：

- **D（部分观测状态估计）对你有隐藏价值**：TerraState 的输入本来就是 cloud-masked histories，云掩膜数据（`s2_dlmask`、`s2_avail`、`s2_SCL`）已在每个 cube 里，但论文中"云鲁棒"只是数据描述，**没有作为实验证据出现**——这是一个可以低成本填补的空洞；
- **E（未来事件预测）是唯一"既是真下游、又不背离主线"的扩展方向**：未来植被胁迫检测的输入仍然是历史影像 + 未来天气，完全消费状态和转移；
- **F（不确定性）明确不做**：TerraState 是确定性模型，不要为了"像世界模型"硬拼概率指标（89 号文已冻结此纪律）。

**结论 2：主流是 B + C 的组合，且主流工作都不做传统下游。**

EO-WM 和 VegSim 的实验结构都是「事实未来预测（B）+ 情景/极端响应（C）+ 消融/案例」，**两者都没有做任何普通分割/分类/检测下游**。这直接回答你的顾虑：**TerraState 不做洪水/城市扩张，不是缺陷，而是这个类别的标准形态。**

各代表工作的实验安排对照（内化用）：

| 工作 | 主任务 | 证据链怎么搭 | 传统下游 |
|---|---|---|---|
| **EO-WM**（2026 预印本） | 历史影像+天气 → 未来 20 帧多光谱 | 标准像素预测 + Extreme Summer + Seasonal Matched-Pair + 天气条件模块分析 | **0 个** |
| **VegSim**（2026 预印本） | 稀疏 NDVI+天气 → 概率 NDVI 轨迹 | ID/OOD + 四种气象情景 + 法国 2022 干旱案例 + 概率指标 | **0 个** |
| **RemoteBAGEL**（预印本） | 中心影像+方向 → 邻接影像 | general/flood/urban/rural 子集 + 视觉质量 + 指令服从 | **0 个** |
| **RS-WorldModel**（2026 预印本） | 变化理解 QA + 文本条件未来生成 | QA 与生成联合主任务 | **0 个** |
| **ViT-Koop**（ICCVW 2025） | Koopman 潜状态转移 EO 预测 | SEVIR / ENSO / EarthNet2021 三预测基准 | 0 个（也未自称世界模型） |
| **SkySense**（CVPR 2024，基础模型） | 多模态遥感基础表征 | — | **16 数据集 / 7 类任务** |
| **SatMAE**（NeurIPS 2022，基础模型） | 时序/多光谱 MAE 预训练 | — | 分类 + 分割迁移 |
| **CROMA**（NeurIPS 2023，基础模型） | 雷达-光学对比+掩码重建 | — | 4 分类 + 3 分割基准 |

**规律**：下游任务数量与主张的"广度承诺"成正比。SkySense 主张 universal interpretation，必须用 16 个数据集兑现；EO-WM/VegSim 主张 weather-driven forecasting，靠 OOD/极端/情景兑现，一个传统下游都不需要。

**结论 3：TerraState 的独特位置 = B + C + 一个别人没有的差异点。**

那个差异点是**状态承载性的可证伪测试（Q2）**：移除状态路径看预测退化多少、带配对 bootstrap 置信区间。EO-WM 做的是输出层响应诊断，VegSim 做的是情景滚动，都没有这个测试。**扩展时不要丢掉这个差异点去追别人的广度。**

### 2.3 遥感世界模型 vs 通用视觉世界模型（背景内化）

为了完整内化，还需要知道遥感世界模型在更大的世界模型版图中的位置：

| 分支 | 驱动是什么 | 典型代表 | 与遥感的区别 |
|---|---|---|---|
| **游戏/具身世界模型** | 智能体的**动作** | Dreamer 系列、Genie、GAIA-1 | 驱动是可控动作，可以做真正的策略规划 |
| **自动驾驶世界模型** | 车辆动作 + 交通规则 | GAIA-1、Vista | 同上，且有闭环控制需求 |
| **气象/气候模型** | 初始条件 + 边界强迫 | GraphCast、GenCast、Pangu-Weather | 输出就是驱动本身（天气），物理约束强 |
| **遥感世界模型** | **外生天气/气候驱动**（不可控） | EO-WM、VegSim、TerraState | 驱动不可控 → 没有"策略"，只有情景模拟；观测部分缺失（云）是内在特性 |

**关键差异**：遥感世界模型的驱动（天气）是**外生且不可控**的。这意味着：
- 不能做具身智能那种"规划最优动作序列"
- "反事实"只能是情景模拟（改变输入看响应），不是因果干预
- 云遮挡导致**部分可观测**是任务内在属性，不是数据缺陷

这也解释了为什么 88/89 号文反复强调"不把条件天气模拟说成因果反事实"——同一地点同一时刻"下雨"和"不下雨"的两个真实结果不可能同时被观测，没有反事实真值。

## §3 TerraState 的精确定位与当前证据状态

### 3.1 主线任务的精确命名

> **天气驱动的、部分观测的、固定窗口地表状态预测**
> (weather-driven, partially-observed, fixed-horizon land-surface state forecasting)

每个修饰词都在排除一类误解：

| 修饰词 | 排除了什么 |
|---|---|
| 天气驱动 | 不是纯自回归视频预测（未来驱动是外生输入） |
| 部分观测 | 不是完整观测序列（云遮挡是任务内在的一部分） |
| **固定窗口** | **不是递归 rollout** ← 最容易被误读的一条 |
| 地表**状态** | 输出是 NDVI 而非完整多光谱影像 |

**"固定窗口"必须反复强调**：TerraState 的推理链是从同一个 `z_t` 直接查询各个 horizon（`z_{t+h} = T(z_t, u, geo, h)`），**不是** `z_t → z_{t+1} → z_{t+2}` 的递归推进。这限制了一批看起来自然的扩展（长时 rollout 漂移、闭环稳定性、递归误差累积都不能直接做），也是 Q4 composition 不能靠换指标补上的原因。

### 3.2 当前证据状态速览（以冻结文档为准）

**已成立**（boundary80 checkpoint，全部冻结协议）：

| 证据 | split | 数值 | 判定 |
|---|---|---|---|
| Q1 预测前提 | OOD-t | R²=0.56935 / RMSE=0.15059 | PASS（内部判据） |
| Q1 预测前提 | val | R²=0.49732 / RMSE=0.15729 | SHORT（差 0.005） |
| Q2 状态承载 | OOD-t | 闭合 ΔR²=+0.01997，CI [+0.0142,+0.0302] | **LOAD_BEARING** ✅ |
| Q2 状态承载 | val | 闭合 ΔR²=+0.01121，CI [+0.0064,+0.0259] | **LOAD_BEARING** ✅ |
| Q3 天气响应保真 | 极端 84 对 | actual > donor > mean（端点均显著） | **FIDELITY PASS** ✅ |
| Q3 热旱增强 | 极端 84 对 | 交互项 CI 含 0 | **FAIL**（不得声称增强） |

**明确不成立/未证明**：
1. Q3 不是因果反事实；
2. 热旱增强 guard FAIL——不能声称极端子集有额外机制；
3. 无 Q4 composition 证据（划分已随权重冻结、代码路径存在、但从未训练过组合律）；
4. 不是递归 rollout 世界模型；
5. 输出是 NDVI，不是多光谱影像模拟器；
6. 无独立分类/分割/检测下游；
7. 主表不是第一（ContextFormer OOD-t R²=0.620 > TerraState 0.569）。

**一个可量化的框架化事实**（85 号文实测）：TerraState ≈ 6.06M 骨干 + **1.12M 状态机制**，而官方 ContextFormer 是 6.1M。即：多付 1.1M 参数 + 约 0.05 R²，买到一个可证伪的状态接口。这比"我们排第六但机制更好"更有说服力。

**一个必须先处理的血统问题**（85 号文发现，扩展实验的阻塞项）：正文写 40 epochs / 14,880 updates，但产出全部 Q1/Q2/Q3 数字的 boundary80 实为 epoch 31 / step 11,904；14,880 的 `checkpoint_last.pt` 已找回，重跑纯推理即可钉死基准点。

## §4 下游任务的选择逻辑与五条判据

### 4.1 五条判据（按优先级排序）

1. **必要性检验**：去掉未来驱动，这个任务还成立吗？成立 → 不是世界模型下游
2. **状态使用检验**：这个任务真的用到 `z_t` 或 `T` 吗，还是只用了骨干特征？
3. **独立性检验**：它提供的证据与 NDVI RMSE 独立吗，还是同一个数字换个名字？
4. **标签真实性检验**：标签是外部独立来源，还是从同一 NDVI 阈值导出的？
5. **课题边界检验**：它会不会变成第二篇论文？

**第 4 条是最容易自欺的一条**：如果"植被胁迫事件"标签完全由真实 NDVI 阈值生成，那么「预测未来胁迫事件」在数学上几乎等价于「预测未来 NDVI 然后取阈值」。它是**同一预测的运营化解释**——有价值（提供 AUROC/onset MAE 这类决策相关指标），但必须标注为**派生事件评估（derived event evaluation）**，不能包装成独立的第二任务。

### 4.2 下游任务谱系全景（世界模型视角的完整候选清单）

按第 E 类（语义未来事件）→ 第 D 类（观测恢复）→ 静态附属的顺序：

#### 第一梯队：未来事件预测类（E 类，与主线同构）

| 任务 | 输入 | 输出 | 指标 | 判据检验 |
|---|---|---|---|---|
| **未来植被胁迫事件检测** | 历史影像 + 未来天气 | 未来是否发生显著 NDVI 下降 | AUROC / AUPRC / F1，不同 lead time 下的预警曲线 | ✅ 全过（标签派生需标注） |
| **未来胁迫严重度回归** | 同上 | 最大降幅 / 峰值 / 累计强度 | severity MAE | ✅ 全过 |
| **未来胁迫起始时间预测** | 同上 | onset 时间 | onset MAE | ✅ 全过，最适合极端天气叙事 |
| **未来异常范围分割** | 同上 | 空间异常掩膜 | extent IoU / F1 | ✅ 过，但需避免"NDVI 阈值换名" |
| **未来语义变化预测** | 历史 + 未来驱动 | 未来土地覆盖变化 | 变化检测指标 | ✅ 概念最强，但需独立语义标注（DynamicEarthNet），接近新项目 |
| **未来作物胁迫/物候/产量** | 历史 + 未来天气 | 未来物候期/产量 | 物候 MAE / 产量 R² | ✅ 概念好，需新数据集与驱动对齐 |
| **未来洪水范围预测** | 洪水前状态 + 未来降雨 | 未来淹没掩膜 | IoU / F1 | ✅ 概念极佳，但几乎是第二篇论文 |

#### 第二梯队：状态复用探针类（介于世界模型与基础模型之间）

| 任务 | 形式 | 证明什么 | 关键设计要求 |
|---|---|---|---|
| **冻结状态低样本探针** | 冻结 `z_t`/`z_{t+h}`，训小 head 预测未来胁迫 | 状态不仅承载预测，也是可复用动态表征 | **必须含"history feature ⊕ 未来天气原始向量"对照**，否则优势可能只来自多看了天气 |
| **静态土地覆盖 probe** | 冻结状态 → LC 分类 | 状态保留地表语义 | 只能作附属，不是主下游 |

低样本探针的完整对照组设计（缺一个就不成立）：

| # | 表征 | 见过未来天气 | 作用 |
|---|---|---|---|
| 1 | `z_{t+h}`（推进后状态） | ✅ | 主张的表征 |
| 2 | `z_t`（context-only 状态） | ❌ | 隔离"推进"本身的贡献 |
| 3 | 同骨干 history feature | ❌ | 隔离"骨干"的贡献 |
| 4 | **history feature ⊕ 未来天气原始向量** | ✅ | **隔离"信息量"与"状态结构"**（最关键、最常被漏掉） |
| 5 | 随机初始化 / 简单统计特征 | — | 地板 |

报告形式：1% / 10% / 100% 标签比例下的 label-efficiency 曲线，不是单点数字。

#### 第三梯队：观测恢复类（D 类，TerraState 线只做分层分析版）

| 任务 | TerraState 线怎么做 | Stage1–1.5 线怎么做 |
|---|---|---|
| 云遮挡鲁棒性 | 按云覆盖/有效帧数**分层报告** Q1+Q2（不改模型） | 云补全作为核心下游 |
| 缺测鲁棒性 | 人工遮挡注入 → 性能退化曲线 | 同上 |
| S1↔S2 跨模态补全 | ❌ 不做（无 S1 通道） | ✅ 核心任务 |

#### 明确不做清单（含理由）

| 任务 | 为什么不做 |
|---|---|
| 静态洪水分割 | ①输入不含未来驱动（判据 1 不过）；②模态不匹配（主流用 SAR，TerraState 是 S2 光学+E-OBS）；③叙事稀释 |

| 普通目标检测（DOTA 类） | 与状态动力学关系最弱，明确不做 |
| 概率化/多未来 | 确定性模型硬拼概率指标违反诚实性纪律 |

## §6 走 TIP 的实验设计策略

### 6.1 TIP 的定位风险（必须先正视）

TIP 全称 *IEEE Transactions on Image Processing*，核心社区是图像处理/视觉方法论。TerraState 当前形态与它的张力：

| 张力点 | 现状 | TIP 期待 |
|---|---|---|
| **输出形态** | NDVI 单通道标量场 | 图像/多通道输出 + PSNR/SSIM/SAM/ERGAS |
| **贡献类型** | 证据协议（可证伪状态测试） | 方法/算子层面的技术贡献 |
| **主表位置** | 第六（ContextFormer 三项指标领先） | 期刊读者对精度竞争力期待更高 |
| **任务归属** | 遥感时序预测 | 该任务的自然归属其实是 TGRS/RSE/ISPRS |

**坦率判断**：保持"NDVI 回归 + 证据协议"形态，TGRS 比 TIP 更对口（这与 Codex 调研结论一致，张力尚未解决——本文不替你下结论，只把两边的实验代价摆清楚）。**若坚持 TIP，多光谱输出改造（T5）基本是必需项**，那是数周的 C4 级工作。

### 6.2 TIP 最小连贯证据包（按证据强度排序）

| 优先 | 内容 | 成本 | 为什么 TIP 需要 |
|---|---|---|---|
| **T1** | 血统修复：14,880 权重重跑 Q1/Q2/Q3，确立 canonical checkpoint | C0 | 期刊可复现性硬指标 |
| **T2** | Q1+Q2 完整偏移矩阵（iid/ood-t/ood-s/ood-st） | C0 | 消除"仅时间偏移"Limitation |
| **T3** | 云遮挡/有效帧数/lead-time/LC 四维分层 | C1 | 期刊分析深度 |
| **T4** | 训练级 matched ablation（4 arm，约 12h 算力） | C3 | 回应"测试时切路≠训练级必要性" |
| **T5** | **多光谱输出 + PSNR/SSIM/SAM/ERGAS** | **C4** | **让论文落在 Image Processing 射程内（分水岭）** |
| **T6** | 未来胁迫检测/severity/onset 下游（+SPEI 外部参照） | C2 | 期刊应用价值 |
| **T7** | 效率剖面（参数/FLOPs/显存/延迟） | C0 | 方法完整性 |
| **T8** | 第二独立数据设置（DynamicEarthNet 或作物数据集） | C5 | 期刊泛化期待 |

### 6.3 TIP 路线下"主表不第一"的叙事选择

| 叙事 | 说法 | 风险 |
|---|---|---|
| 保持现状 | Q1 只是前提，价值在 Q2/Q3 | 期刊审稿人比会议更可能要求精度竞争力 |
| **换轴（推荐）** | 在"可检验性/鲁棒性"轴上领先，明确放弃 clear-sky 精度轴 | 需要新轴上的完整证据（云鲁棒分层 T3 + 训练级消融 T4 恰好提供） |
| 追平 | 投算力把 R² 提到 ContextFormer 水平 | 与"faithfulness–accuracy tradeoff"叙事自相矛盾 |

注意：证据文档明确警告 tradeoff 是"observed phenomenon, not a proven causal claim"。换轴叙事要成立，必须先用 T4 的训练级消融把 tradeoff 从观察升级为机制证据。

## §7 走 ICLR 的实验设计策略

### 7.1 ICLR 与 TIP 要的不是同一种"更多实验"

| 维度 | TIP 想看到 | ICLR 想看到 |
|---|---|---|
| 新意来源 | 方法/算子的技术贡献 | **概念或机制的洞察** |
| 实验广度 | 分层、鲁棒、效率、第二数据集 | 假设-验证闭环，可以窄但必须锐利 |
| 精度要求 | 较高 | 较低（若机制洞察够强） |
| 协议创新 | 次要 | **可以是主贡献** |
| 输出形态 | 偏好图像/多通道 | 不关心 NDVI 还是影像 |
| 负结果 | 不受欢迎 | **可以是贡献**（若解释清楚） |

**关键推论**：TerraState 当前形态（NDVI 回归 + 证据协议 + 主表第六）**对 ICLR 比对 TIP 更友好**——不需要 T5 多光谱改造，Q2/Q3 本身就是卖点，精度不领先可容忍。

### 7.2 三个 ICLR 叙事候选

**候选 A：状态承载性是可测量的，且与精度解耦**
- 主张：预测精度与内部状态是否真正承载预测是两个可分离测量的属性；高精度模型可能有空心状态
- 需要：在多个模型上测同一套状态承载性指标，展示精度排序与承载性排序不一致；训练级消融证明 tradeoff 机制性
- 为什么强：这是关于世界模型**评测本身**的洞察，可推广到 EO 之外——"大家一直在用错的尺子"
- 注意：ContextFormer 是 context-only 架构，无显式 `z_t + T` 分离，"在它身上跑 Q2"需要先定义表征层面的干预协议，不能直接套脚本

**候选 B：驱动响应保真度的可测量层级（matched donor 阶梯）**
- 主张：在无反事实真值的物理系统里，actual > donor > climatology 阶梯建立响应保真度的可测量分级——不是因果识别，但远强于扰动敏感性
- 需要：Q3 阶梯（已有）+ 在多个模型上跑同一阶梯证明可区分模型 + 对抗"任何 weather-conditioned 模型都会响应"的 null 假设
- 为什么强："把不可能的事降级为可做的事并说清边界"是 ICLR 认的路数

**候选 C：固定窗口 vs 递归推进的组合律检验（Q4）**
- 主张：`T(T(z,h1),h2) ≈ T(z,h1+h2)` 是否成立决定模型学到的是动力学还是 horizon 查表
- 现状：划分已随 checkpoint 冻结、`composed_state()` 存在、**组合律从未被训练** → 实测很可能违背
- 风险与机会：若严重违背，叙事从"证明动力学"翻转为"固定窗口模型没有真动力学"——**后者也是可发表的负结果**，但要改写整个故事
- 写作边界：即使通过也只能说"共享转移在端点组合下保持一致"，不能说"学到递归动力学"

### 7.3 ICLR 最小证据包

| 优先 | 内容 | 成本 | 服务哪个候选 |
|---|---|---|---|
| **I1** | 血统修复 | C0 | 全部（底线） |
| **I2** | **同协议在 ContextFormer/B4 上跑 Q2+Q3（跨模型机制测量）** | C0–C1 | **A/B 核心（分水岭）** |
| **I3** | 训练级 matched ablation | C3 | A（tradeoff 机制性） |
| **I4** | Q1+Q2 偏移矩阵 | C0 | 全部 |
| **I5** | 状态诊断（有效秩/塌缩/lead-time 分解） | C1 | A |
| **I6** | Q4 composition 协议 + 实测 | C1（纯推理测量）→ C4（若要改模型） | C 核心 |
| **I7** | 状态复用低标签探针 | C2 | A |

## §8 分叉决策与执行排期

### 8.1 共享与冲突

**前 4–6 周不需要选边**——血统修复、偏移矩阵、分层分析、训练级消融、状态探针对两边都有用。

**真正冲突的投入**：

| 冲突项 | TIP 要 | ICLR 要 |
|---|---|---|
| 输出形态 | 多光谱 + PSNR/SSIM（T5，C4 级数周） | 不需要（零收益） |
| 基线用途 | 精度竞争力 | 跨模型机制测量（证明精度≠机制） |
| 叙事重心 | 方法/算子贡献 | 概念/评测洞察 |
| 第二数据集 | 期刊期待（T8，C5） | 可选 |
| Q4 | 可选 | 可能是主线（I6） |

### 8.2 分叉决策规则（由实验结果决定，不由偏好决定）

```
第 0 周     血统修复（阻塞项，先做）
第 1-2 周   C0：偏移矩阵 + 基线同协议 + 效率
第 3-4 周   C1：云/帧数/lead-time/LC 分层 + 状态诊断 + Q4 纯推理实测
第 5-6 周   C3：训练级 4-arm 消融（约 12h 算力）
─────────── 分叉决策点 ───────────
若 I2 发现精度与状态承载性解耦     → 走 ICLR（候选 A/B），不需要多光谱改造
若 I2 未发现解耦                   → 洞察不成立，走 TIP，投入 T5 多光谱 + T8 第二数据集
若 Q4 实测组合律严重违背           → 本身是发现，可作 ICLR 负结果叙事（候选 C 变体）
```

**这个规则的好处**：前 6 周的工作在任何结局下都不浪费；决策由数据驱动。

### 8.3 与 TGRS 张力的处理方式

Codex 调研结论（TGRS 更合适）与你的倾向（TIP）的张力**保留到文献调研+正文对话拉取完成后再综合裁决**。本文能给的边界条件：
