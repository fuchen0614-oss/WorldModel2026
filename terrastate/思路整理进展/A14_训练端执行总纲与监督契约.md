## 1. 服务器约束与权限边界

从用户指定的“下载并登录 EasyConnect”任务（ID `01a05c3b-d1a5-7ff0-a67b-f9aa4e17f034`）已核对：用户要求安装和所有项目操作严格局限在 `/data/zs`；此前数据已下载，空间一度约 17GB。该空间数字是历史记录，不是当前实测。

### 1.1 硬性禁止

- 不在 `/data/zs` 之外创建、修改、移动、删除项目文件、缓存、虚拟环境或配置。
- 不使用 sudo，不改系统 Python/CUDA/驱动，不改系统包，不安装全局依赖，不写 `~/.bashrc` 等外部配置。
- 不清理其他用户文件，不占用别人 GPU，不杀死不属于本次任务的进程。
- 不为了“撤销过去越界写入”而自动去外部目录删除东西；列出证据交用户另行处理。
- 不运行 `git reset --hard`、`git clean`、强推，不覆盖历史权重、冻结结果、manifest、旧结论。
- 不执行一键 setup 下载脚本来代替环境盘点；它可能触发大规模下载。E1 已完成，不因基线权重暂缺重新下载整包。
- 不安装 `earthnet-models-pytorch` 的 PyPI 包；历史项目明确警告其依赖可能锁定旧 torch。使用已有只读上游代码与既有导入方式。
- 不把 checkpoint 中的历史 `/mnt/...` 路径当作本机输出位置。所有路径必须映射到当前根目录。
- 不把数据、权重、访问令牌或服务器凭据写进 Git，也不上传公开服务。

只读进程/设备状态查询可以用于资源盘点；不要在根目录或其他用户目录递归搜索数据。若输入通过软链接指向 `/data/zs` 之外，报告并停止使用该路径，等待用户澄清。

### 1.2 路径与缓存

所有写入必须检查最终解析路径，而非字符串前缀：`/data/zs2` 不是 `/data/zs`；软链接不能绕过边界。创建前检查父目录 realpath；若 `.git` 是指向外部的 worktree 管理路径，不得写 Git 状态。

建议统一：

```text

/data/zs/terrastate_tip_runs/       新结果根目录
/data/zs/terrastate_tip_runtime/    缓存、临时目录、测试 home
```

启动计算进程前将 TMPDIR、TMP、TEMP、XDG_CACHE_HOME、MPLCONFIGDIR、TORCH_HOME、HF_HOME、PIP_CACHE_DIR、PYTHONPYCACHEPREFIX、CUDA_CACHE_PATH 指向上述根内目录。实际使用的 Triton/JIT/W&B 等缓存同样配置；默认离线日志，不启用云同步。

不全局修改 HOME 来破坏 SSH/Git 凭据查找；计算子进程确有需要时可使用根内隔离 HOME。检查 pytest、编译器及第三方库临时文件位置。不能保证根内写入的工具，先不要运行。

### 1.3 磁盘与 GPU

先测当前可用磁盘和已有任务，不沿用“17GB”的旧值。默认新增输出预算先设 **2GiB**、保留空间至少 **10GiB**，仅作为本任务保守工程闸门，不是论文标准。不能满足时只做轻量盘点，报告需要多少空间。

运行前估算最大新产物、临时文件和 checkpoint 大小：`可用空间 - 预计峰值新增空间 >= 保留空间` 才开始。禁止全量保存所有模型×种子×分段的像素预测；使用逐样本充分统计量和少量冻结可视化样例。

不因训练中空间不足自动删除旧结果。只对本次 run 明确登记的临时产物提出清理清单，获得授权后再清理。每个长任务记录 PID、命令、GPU、输出路径；停止时只针对该 PID。

## 5. 状态机与工作单位

统一状态：`NOT_STARTED`、`IMPLEMENTED`、`UNIT_TESTED`、`SMOKE_PASSED`、`FORMAL_EVALUATED`、`AUDITED`、`BLOCKED`。

- IMPLEMENTED：代码存在，未说明正确。
- UNIT_TESTED：合成/确定性测试通过，未说明真实数据科学效应。
- SMOKE_PASSED：少量真实数据流程成功，不是正式样本结果。
- FORMAL_EVALUATED：冻结完整范围出数，包含负结果。
- AUDITED：来源、统计、图表和结论一致，人工或独立复核通过。

工程状态与科学结论分列。一次实验可以 FORMAL_EVALUATED 且结论不支持假设；不应为获得 PASS 重跑到有利为止。

每个 run 独立目录：

```text
<RUN_ROOT>/<UTC日期>_<任务ID>_<model>_<seed>/
  run_manifest.json
  resolved_config.json
  commands.txt
  environment.txt
  input_hashes.json
  stdout.log
  tests_report.json
  per_cube_metrics.csv
  aggregate.json
  plot_data/
  figures/
  status.json
  report.md
```

不存在的产物不创建假空表冒充完成。科学结果 JSON 缺值使用 null 并给 reason，禁止将 NaN、空值或加载失败写成零。

## 8. 禁止的科学捷径

- 不声称 Q4 修正后 19/19 等于共同后缀已通过。
- 不用保存训练 optimizer 的测试替代 runtime state 恢复。
- 不仅比较两预测相近，必须分别比较事实 GT。
- 不把未来 GT 编入状态初始化，不用未来图像填补历史云缺失，不在续推过程中悄悄重新读历史。
- 不用随机合成天气的成功演示证明气候情景真实性。
- 不把 Contextformer 的官方 r² 当 pooled R²；不把历史 bootstrap CI 改名为聚类 CI。
- 不跨模型 checkpoint 互换潜状态；不同潜空间坐标没有对齐保证。
- 不拿未原生支持变跨度跳转的固定步长基线强行测试并标失败。
- 不为了让 latent distance 小而事后挑归一化、删高距离样本或修改阈值。
- 不删除 Q3 热旱交互未支持、天气顺序效应随时距变化、精度落后基线等结果。
- 不把多种子误差当作已校准预测概率；当前不要求概率头。

## 9. 遇到问题的处理顺序

1. 工程异常：定位样本、shape、dtype、索引、mask、NaN/Inf、版本；停止当前失败任务，保留日志。
2. 时间/天气/prior 错位：先加确定性单元测试，再修适配代码，修复后的结果新版本生成。
3. 指标聚合异常：保留旧结果，写明确新公式和样本资格；先算合成案例，再全量汇总，不能只为提高得分改口径。
4. 真实科学效应不足：报告效应和 CI，先讨论训练目标或主张收窄，不直接大改骨干。
5. 需要新架构：给出单一假设、最小改动范围、消融和训练预算，获得确认后启动；旧 C1 不覆盖。
6. 空间/GPU不足：停止新增重任务，继续文档与小测试；不自动下载其他“小一点”数据集。
