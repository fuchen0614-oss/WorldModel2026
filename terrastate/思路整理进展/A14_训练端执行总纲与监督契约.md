### 2.2 C0R 的定位与训练决策

C0R 是同结构、同初始化、同标签时刻的直接监督对照；C1 将额外端点监督改走递归分段。C0R 在分段使用中退化本身不是实现错误。其作用是隔离训练路径整体效果，仍需固定步长和简单一致性对照判断独特性。

两臂训练时部分 q 继续更新，最终 prior/z0 也可能不同；不能把整体差异全部归于 T。至少并列两臂 prior-only 精度和残差量级。若后续强化记忆机制主张，可条件启动固定共同编码器/prior 配对、跨段仅传当前读出的瓶颈对照或空间池化状态对照；先给单一假设及预算，不自动增加全部训练臂。

近期训练顺序：**现有权重补评估 → 最小固定步长/输出一致性对照 → 配对多种子及必要计算预算对照**。若方法与配置未改变，补独立后续训练种子，不把同一权重重复评估当重训；只有确认需要改变训练目标后才建立新版 C1。第二数据继续延期。

## 5. 状态机与工作单位

统一状态：`NOT_STARTED`、`IMPLEMENTED`、`UNIT_TESTED`、`SMOKE_PASSED`、`FORMAL_EVALUATED`、`AUDITED`、`BLOCKED`。

- IMPLEMENTED：代码存在，未说明正确。
- UNIT_TESTED：合成/确定性测试通过，未说明真实数据科学效应。
- SMOKE_PASSED：少量真实数据流程成功，不是正式样本结果。
- FORMAL_EVALUATED：冻结完整范围出数，包含负结果。
- AUDITED：来源、统计、图表和结论一致，人工或独立复核通过。

工程状态与科学结论分列。一次实验可以 FORMAL_EVALUATED 且结论不支持假设；不应为获得 PASS 重跑到有利为止。

每个 run 独立目录：

## 8. 禁止的科学捷径

- 不声称 Q4 修正后 19/19 等于共同后缀已通过。
- 不用保存训练 optimizer 的测试替代 runtime state 恢复。
- 不仅比较两预测相近，必须分别比较事实 GT。
- 不把未来 GT 编入状态初始化，不用未来图像填补历史云缺失，不在续推过程中悄悄重新读历史。
- 不用随机合成天气的成功演示证明气候情景真实性。
- 不把 Contextformer 的官方 r² 当 pooled R²；不把历史 bootstrap CI 改名为聚类 CI。
- 不跨模型 checkpoint 互换潜状态；不同潜空间坐标没有对齐保证。
- 不拿未原生支持变跨度跳转的固定步长基线强行测试并标失败。
- 不为了让 latent distance 小而事后挑归一化、删高距离样本或修改阈值。
- 不删除 Q3 热旱交互未支持、天气顺序效应随时距变化、精度落后基线等结果。
- 不把多种子误差当作已校准预测概率；当前不要求概率头。

## 9. 遇到问题的处理顺序

1. 工程异常：定位样本、shape、dtype、索引、mask、NaN/Inf、版本；停止当前失败任务，保留日志。
2. 时间/天气/prior 错位：先加确定性单元测试，再修适配代码，修复后的结果新版本生成。
3. 指标聚合异常：保留旧结果，写明确新公式和样本资格；先算合成案例，再全量汇总，不能只为提高得分改口径。
4. 真实科学效应不足：报告效应和 CI，先讨论训练目标或主张收窄，不直接大改骨干。
5. 需要新架构：给出单一假设、最小改动范围、消融和训练预算，获得确认后启动；旧 C1 不覆盖。
6. 空间/GPU不足：停止新增重任务，继续文档与小测试；不自动下载其他“小一点”数据集。
