# QUESTIONS_AND_DECISIONS

记录本轮**自主做出**的实现选择与理由，供事后审查。无需用户当场回答。

1. **C0R 标准预测补测**：查证 C0R 无同协议标准预测（仅有 Q4 `c0r_score`），故按授权用现有正式权重补测；
   协议与多 seed C1 seed42 逐参数一致（同 manifest/掩码/评分器），4 卡并行，输出落在本轮目录。
2. **GPU 分配**：GPU 3/4/5 空闲优先使用；GPU 0 被他人占用（~21 GB/100%），C0R 的 ood-s 分片放在 GPU 0 上共享，
   因为该任务是**正确性评测而非计时**，共享不影响结论。未停止任何他人任务。
3. **T4B 样本单位**：发现按 `cube` 聚合会把多个 receiver 合并（238 vs 2078），改为 **`dataset_index`**，
   并按 `full_suffix_1_to_10` 与 `endpoint_h10` 两个范围分别报告；修正后点估计与原 v8 表逐位一致。
4. **T4B 三口径**：按 E1 复核笔记与提示词要求，receiver 等权 / 地理组等权 / pooled 分别给自洽点估计与 CI，
   不按显著性挑选主口径。
5. **Fig.5 数据源**：使用 E1 交付的**官方分窗指标**（`rmse_0_5..rmse_15_20`，三 seed 齐全），
   明确标注为"分窗预测误差"、n=3、样本标准差、不插值；不使用已停止的 `horizon_parallel` 产物。
6. **F1/F2**：只找到 2026-07-29 旧设计图，未经本轮代码核对 → 交付**绘图说明**，不冒称最终图。
7. **FSR**：仅登记路径、定义与已知统计问题（训练调用数≠FLOPs≠查询效率），不进 Table 3、不做新分析。
8. **效率**：新增的 C1 运行时测量在检测到外部占卡的环境下完成，全部标为**受限测量**；
   不据此声称通用更快。
9. **B=4 分支天气后缀**：为测成本，用固定种子对真实未来天气的日序做确定性置换生成 4 个后缀；
   该构造**仅用于成本测量**，不作为任何天气科学结论。
10. **本地同步**：只同步表格/图件/报告等轻量交付到
    `思路整理进展/交付包/<本轮目录名>/`，不同步大型预测影像。

## 修正版（本轮定向修复）新增的实现选择

11. **主口径的声明时点**：Table 4B 的 receiver 等权在**看任何 CI 之前**就被声明为主口径，
    依据是“样本单位＝receiver，等权即样本等权”这一估计对象定义，而不是它是否显著。
    `geo_equal` / `pixel_pooled` 降级为敏感性口径并在表中标注角色。
12. **1.80× 的处理**：v1 报告的 1.80× 不删除、也不维持，而是**拆解**为分阶段成本 + 成本模型公式。
    原因是 v1 的 reuse 路径在计时区间内仍调用了一次 `initialize()`，且适配器每次 advance/decode
    都做全量 state-dict 哈希校验，使该比值**不是**纯计算加速比。分阶段测量与公式可复算，单一倍率不可。
13. **空间分组**：核对后确认 v1 注释（0.5°）与实现（`.round(1)`＝0.1°）矛盾，而 A14B 合同**未规定**
    网格分辨率。因此**不改主结果**（保持 v1 分组，已报告数字一个不动），改注释使其与实现一致，
    并用同一批已算好的评分**另补** 0.5° 敏感度结果。
14. **验收脚本**：新增 `code/verify_pairing.py` 做逐评分记录配对核对。它只读已写好的 parquet，
    因此不触发重新推理；同时把空间分组定义的分组数一并核对，作为第 13 条的机械证据。
15. **自足性**：v1 的 9 个 py 脚本 + `run_all.sh` 都读外部指针文件 `/data/zs/fsr_tmp/closure_dir.txt`，
    `run_all.sh` 还调用外部脚本 `/data/zs/fsr_tmp/finalize_package.sh`。修正版全部改为
    以脚本自身位置推导包根目录，并把打包逻辑内置为 `code/finalize_package.py`。
16. **账本**：改为用 Python `csv` 从结构化记录写出，并在写出后**断言**每行字段数与表头一致
    （同时检查 csv 解析与朴素逗号切分两种读法）；状态从产物派生，避免再次出现“启动时写下、
    完成前冻结”的过期状态。
17. **中文编码防护**：修正过程中发现一次 PowerShell `Get-Content -Raw`/`Set-Content` 往返
    会把 UTF-8 中文按 GBK 解码而**吞掉紧跟全角括号的引号**，造成不可逆损坏。因此修正版的
    所有脚本改写都改由 Python 以显式 UTF-8 完成，并在构建时对每个文件做
    “无私有区码点 + 中文字符数不减少 + 可编译”的差分校验。
18. **增量执行（整体整理阶段）**：只改动了 `code/gen_reports.py`（文字、CSV 字段、展示方案）、
    `code/run_all.sh`（新增末尾一致性门）与新增的 `code/verify_consistency.py`。
    按要求**只部署这三个文件**，未重建整个 `code/` 目录，也未重跑评分配对、bootstrap 或效率测量；
    计算脚本与测量协议未变，因此这些检查按“代码与输入未变”的理由复用，
    其当前哈希记录在 `reports/VALIDATION_REPORT.md` 的“复用与重跑说明”一节中。
19. **展示方案**：新增 `reports/PRESENTATION_PLAN.md`，集中回答“先讲什么、哪些放正文、
    每项强调什么又要限定什么”。逐项的科学问题、使用结果、结论、展示定位与限制写入
    `reports/EVIDENCE_INVENTORY.csv` 的新列，主张分层写入 `CLAIM_EVIDENCE_MATRIX.csv` 的
    `evidence_role` / `where` 列，**不再生成功能重复的汇总文档**。
20. **末端一致性门**：新增 `code/verify_consistency.py`，机械核对表 / CSV / 图 / 主张 / 来源
    相互对齐，并自动检查措辞纪律（“不劣于”“所有窗口”“1.80”只能出现在其明确的否认语境中）。
    它是本轮的交付签署检查，输出 `reports/CONSISTENCY_CHECK.md`。
