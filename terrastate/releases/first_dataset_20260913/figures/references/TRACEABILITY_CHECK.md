# 数值可追溯性核对记录

日期：2026-09-12（UTC）。范围：本轮交付的 `OVERVIEW.md`。
目的：确认总览中出现的每一个数值都能追溯到冻结产物或本轮派生统计，且没有在转录中发生漂移。

---

## 1. 方法

`check_traceability.py`（本轮新增，只读）执行两步核对：

**第一步 · 显示精度核对（舍入感知）。**
从 `OVERVIEW.md` 提取全部小数位 ≥ 3 的数值（共 **382** 个不同的值），对每一个值按其打印精度 `nd` 检查：

> 存在某个来源数值 `s`，使得 `round(s, nd) == 打印值`

来源数值池由下列文件中的全部数字构成（共 **1509** 个不同的值）：

| 类别 | 文件 |
|---|---|
| 多 seed 标准评测 | `E1_summary_values.csv`、`E1_per_seed_values.csv` |
| 冻结表（CSV） | 展示包 `tables/Table1/3/4A/4B/5/6A/6B/7*.csv`；冻结修复包 `tables/Table3/Table7*.csv` |
| 冻结表（Markdown，含仅以文本形式出现的量） | `Table3_training_mechanism.md`、`Table7_efficiency_state_reuse.md`、`Table5_weather_response.md`、`Table4A_state_load_bearing.md`、`Table6B_common_suffix.md` |
| 冻结运行时 JSON | `metrics/T7_c1_runtime.json` |
| 本轮派生统计 | `metrics_derived/` 下全部 CSV 与 provenance JSON |

采用舍入感知而不是逐字符比对，是因为来源以全精度存储（例如 `0.15552902418674006`），而总览按表格统一小数位显示（`0.155529`）。逐字符比对会把合法的显示舍入误报为不可追溯。

**第二步 · 关键比例重算。**
对本轮新引入的效应量，直接用冻结源 CSV 重新计算，确认与正文引用的数字一致；这些数字同时登记在 `metrics_derived/DERIVED_STATS.csv`。

## 2. 结果

**显示精度核对：382 个值中 363 个在来源数值池中直接找到（或其舍入值命中）；19 个未命中。**

19 个未命中的值全部是 **6 位小数的配对差值**，即冻结表 3 中的 `delta_C0R_minus_C1` 列与表 4B / 表 5 的配对差值列：

```text
0.000111  0.000222  0.000273  0.000302  0.000369  0.000411  0.000459
0.000510  0.000513  0.000684  0.000817  0.000834  0.001046  0.001320
0.001441  0.001679  0.002841  0.00058   0.00083

未命中的原因只有一类：**这些差值是冻结表在生成时按 6 位小数写入的派生量，其未舍入原值不在任何产物中。** 冻结 `Table3_training_mechanism.csv` 的 `delta_C0R_minus_C1` 列本身就是 6 位小数（例如 `-0.0008342142183561663` 写成表内 6 位形式，与 CSV 一致）；因此以 6 位精度比对时不能命中全精度池。

## 3. 范围与限制

1. 本核对只验证**数值是否可追溯**，不重新判定任何统计显著性，也不改变任何口径。
2. 数值池同时包含官方 LC-balanced 与 pooled 两套口径的来源文件；核对过程只做字符串/数值匹配，不进行跨口径换算。总览正文中两条口径始终分列。
3. 本核对不覆盖来源产物本身未记录的量（例如历史训练峰值显存），这类项在总览中一律留空并注明原因。
4. 脚本为只读；除本文件与 `check_traceability.py` 外不产生新的数值产物。派生统计仍以 `metrics_derived/` 为准。

```
