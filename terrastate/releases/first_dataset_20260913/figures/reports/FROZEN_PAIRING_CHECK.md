# PAIRING_CHECK — 逐评分记录的配对核对

本报告只做**机械核对**：用已经写好的评分 parquet，逐条比较两臂是否落在**同一个样本**上。
**不重新推理、不重新评分、不读取预测影像**（影像已按设计删除，见 `provenance/RETENTION_AND_DELETION.md`）。

核对字段：`id`（receiver 身份）、`season`、`lon`/`lat`（像素坐标）、`landcover`（地类）、
`n_obs` 与 `n_obs_full`（有效观测数）。记录键 = `id|season|lon|lat` 并附**同键内出现序号**，
因此同一 receiver 内的重复像素不会被错误折叠。

## 2. 空间分组定义核对（v1 注释与实现的矛盾）

`code/paired_c0r_c1.py` 的 v1 docstring 写的是 “**0.5-degree grid cell**”，
而实现用的是 `.round(1)`，即 **0.1°** 网格。下表给出两种回退网格下的实际分组数：

| split | 组数（tile 优先，0.1° 回退）＝v1 实际使用 | 有 tile 的记录 | 走 0.1° 回退的记录 | 组数（0.5° 回退） |
|---|---:|---:|---:|---:|
| iid_chopped | 80 | 3,561,662 | 0 | 80 |
| ood-t_chopped | 77 | 2,112,698 | 0 | 77 |
| ood-st_chopped | 641 | 0 | 3,075,226 | 399 |
| ood-s_chopped_repaired_v2 | 748 | 0 | 5,773,852 | 454 |

**结论与处理**：

1. **矛盾的性质是文档错误，不是计算错误**：v1 的一切数值都是在 **0.1° 回退网格**上算出来的。
2. **冻结合同未要求 0.5°**：A14B 只要求“按空间 tile / 预定地理组配对重采样”，未规定网格分辨率，
   因此**不需要**为 0.5° 重算主结果。
3. **处理方式**：`paired_c0r_c1.py` 的 docstring 已改成与实现一致，并把规则写成代码常量
   （`PRIMARY_DECIMALS = 1`）；**主结果保持 v1 分组不变**（已报告的数字一个都不变），
   同时在 `metrics/T3_c0r_vs_c1_paired_bootstrap.json` 的 `sensitivity_grouping_0.5deg` 中
   用**同一批已算好的评分**补一份 0.5° 敏感度结果供对照。
4. 历史结果未被覆盖：v1 目录 `first_dataset_closure_20260911T071608Z/` 原样保留。
